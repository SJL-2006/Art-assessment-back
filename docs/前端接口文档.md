# 前端接口文档（艺术测评系统）

> 面向前端开发。覆盖 A（基础底座·账号组织）、B（题库·试卷）、C（作答·判分·评分·统计·证书）三个模块及内容模块（趣味课堂知识）的全部接口。
> 所有字段、枚举、权限均对照后端真实代码（Django 4.2 + DRF 3.14）逐一核对。

---

## 1. 全局约定（必读）

### 1.1 接口基地址与鉴权

- 基地址：`http://<host>:8000`
- 认证方式：JWT（djangorestframework-simplejwt）
  - 先 `POST /api/auth/login/` 拿到 `access` / `refresh`。
  - 之后所有需登录的接口，请求头带：`Authorization: Bearer <access>`
  - `access` 有效期 30 分钟；`refresh` 有效期 7 天，且 `POST /api/auth/refresh/` 会**轮换**返回新的 refresh（前端需覆盖保存）。

### 1.2 统一响应信封

所有 JSON 接口统一包裹为：

```json
{ "code": 0, "message": "ok", "data": { } }
```

- `code = 0` 表示成功；非 0 为错误码（见 1.4）。
- `message` 为中文提示（成功多为 `ok`，部分接口为「操作成功」「上传成功」等）。
- `data` 成功时承载业务数据，错误时一般为 `null` 或字段级错误对象。

**例外**：文件下载类接口（Excel / zip / txt / html）返回**二进制流**，不套信封，前端用「下载」处理（见附录 6.1）。

### 1.3 分页

列表接口统一使用 `StandardPagination`，分页对象放在信封的 `data` 内：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [ ... ],
    "total": 123,
    "page": 1,
    "page_size": 20
  }
}
```

- 查询参数：`page`（页码，从 1 开始）、`page_size`（每页条数，默认 20，最大 100）。
- 前端取列表用 `data.list`，总数用 `data.total`。

### 1.4 错误码

| code | HTTP 状态 | message（中文） | 触发场景 |
| --- | --- | --- | --- |
| 0 | 200/201 | ok 等 | 成功 |
| 400 | 400 | 参数校验失败 | 请求体校验失败，`data` 内是字段级错误（如 `{"name": ["该字段是必填项。"]}`） |
| 401 | 401 | 未登录 / 认证失败或凭证已过期 | 无 token / token 失效 |
| 403 | 403 | 没有操作权限 | 角色权限不足 |
| 404 | 404 | 资源不存在 | id 不存在 / 已软删除 |
| 409 | 409 | 冲突 | 业务冲突（如答卷已提交） |
| 500 | 500 | 服务器内部错误 | 未捕获异常 |
| 502 | 502 | DeepSeek API 调用失败 / AI 返回格式异常 | AI 评分时外部调用失败 |
| 503 | 503 | 未配置 DEEPSEEK_API_KEY… | AI 评分未配 Key |

> 校验失败（400）时，`data` 结构为字段级错误对象，例如：
> ```json
> { "code": 400, "message": "参数校验失败", "data": { "name": ["该字段是必填项。"] } }
> ```

### 1.6 公共字段（BaseModel）

所有业务模型继承 `BaseModel`，包含以下系统字段（请求时**不要传**）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | integer | 主键（BigAutoField），只读 |
| created_at | datetime | 创建时间，只读 |
| updated_at | datetime | 更新时间，只读 |
| is_deleted | boolean | 软删除标记 |
| deleted_at | datetime/null | 删除时间 |

> 所有列表/详情默认过滤 `is_deleted=False`；`DELETE` 为**软删除**（置 `is_deleted=True` + `deleted_at`），不会真删记录。
> 例外：账号管理（User 模型）用 `is_active=False` 做软删。

## 3. A 模块（基础底座·账号组织）

### 3.1 认证 auth

#### 登录

- `POST /api/auth/login/`　权限：公开
- 请求体：

```json
{ "username": "zhangsan", "password": "123456" }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| username | string | 是 | 用户名 |
| password | string | 是 | 密码 |

- 响应 `data`：

```json
{ "refresh": "eyJ...", "access": "eyJ..." }
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| refresh | string | 刷新令牌（7 天） |
| access | string | 访问令牌（30 分钟） |

- 错误：`401`「认证失败或凭证已过期」

#### 刷新令牌

- `POST /api/auth/refresh/`　权限：公开
- 请求体：`{ "refresh": "eyJ..." }`
- 响应 `data`：`{ "access": "eyJ...", "refresh": "eyJ..." }`（refresh 已轮换，需覆盖保存）

### 3.2 用户 users

#### 注册

- `POST /api/users/register/`　权限：公开
- 请求体：

```json
{ "username": "stu001", "password": "Abc123456", "role": "student",
  "real_name": "张三", "phone": "13800000000", "student_no": "S20260001",
  "school": 1, "region": 2 }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| username | string | 是 | 用户名 |
| password | string | 是 | 密码（强度校验） |
| role | string | 否 | 角色，默认 student |
| real_name / phone / student_no | string | 否 | 姓名 / 手机 / 学籍号 |
| school / region | integer | 否 | 学校 ID / 行政区 ID |

- 响应 `data`：注册结果（不含 password）。

#### 当前用户信息

- `GET /api/users/me/`　权限：任意已登录
- 响应 `data`：`{ id, username, real_name, phone, avatar, role, role_display, student_no, school, region, email, date_joined }`

#### 修改当前用户信息

- `PUT /api/users/me/`　权限：任意已登录
- 请求体（均可选）：`{ "real_name": "...", "phone": "...", "email": "...", "avatar": ... }`
- 响应：`message="个人信息修改成功"`，`data` 同当前用户信息。

#### 修改密码

- `POST /api/users/change-password/`　权限：任意已登录
- 请求体：`{ "old_password": "old123", "new_password": "NewAbc123" }`
- 响应：`message="密码修改成功"`，`data=null`

### 3.3 账号管理 accounts

统一 `role` 参数化管理 User。列表查询参数：`role`、`keyword`、`search`（匹配 username/real_name/student_no/phone）、`directly_affiliated`（市直属学校账号过滤）、`ordering`、`page`、`page_size`。

| 接口 | 方法+路径 | 权限 |
| --- | --- | --- |
| 账号列表 | `GET /api/accounts/` | school/district/city/province |
| 创建账号 | `POST /api/accounts/` | school/district/city/province |
| 账号详情 | `GET /api/accounts/{id}/` | school/district/city/province |
| 修改账号 | `PUT/PATCH /api/accounts/{id}/` | school/district/city/province |
| 删除账号 | `DELETE /api/accounts/{id}/` | school/district/city/province |
| 重置密码 | `POST /api/accounts/{id}/reset-password/` | school/district/city/province |
| 批量创建 | `POST /api/accounts/batch-create/` | school |
| 批量导入 | `POST /api/accounts/batch-import/` | school/province |
| 学生身份材料 | `GET /api/accounts/{id}/materials/` | teacher/school |

- 创建/修改账号请求体：

```json
{ "username": "teacher01", "password": "Abc123456", "role": "teacher",
  "real_name": "李老师", "phone": "138...", "student_no": "",
  "school": 1, "region": 2, "email": "", "is_active": true }
```

- 账号列表 `data.list[]` 元素字段：`id / username / real_name / phone / avatar / role / student_no / school / region / email / is_active / date_joined`。
- 重置密码请求体：`{ "new_password": "123456" }`（缺省为 `123456`），响应 `data={ "new_password": "123456" }`。
- 批量创建请求体：

```json
{ "role": "teacher", "prefix": "t", "count": 10, "default_password": "123456",
  "real_names": ["王老师","李老师"], "school": 1, "region": 2 }
```

生成规则：`username = prefix + 3 位序号`（如 `t001`），已存在则跳过。响应 `data={ "created": 10, "usernames": ["t001", ...] }`。

- 批量导入请求体：`{ "role": "student", "items": [ { "username":"s001","password":"123456","real_name":"张三","phone":"...","student_no":"S01","school":1,"region":2 } ] }`，响应 `data={ "created", "skipped", "errors" }`。
- 市直属学校账号查询：`GET /api/accounts/?role=school&directly_affiliated=true` 筛选所属学校为市直属的学校账号。

### 6.2 分数字段（Decimal）序列化类型对照

后端 `DecimalField` 在不同链路序列化类型不一致，前端解析分数时需**兼容 number 和 string 两种**：

| 接口链路 | 类型 | 说明 |
| --- | --- | --- |
| 作答 / 报告（my-assessments、answer-sheets、report 的 score/total_score 等） | **string** | `str(Decimal)` |
| 成绩 / 评分 / 证书 / 统计 / AI 评分（my-scores、students scores、supplement、certificates、ai-grade、stats） | **number** | `float()` |

### 6.3 前端对接注意点

1. **响应统一信封**：先取 `data`，再取业务字段；`code !== 0` 时按 1.4 错误码处理，`message` 直接展示。
2. **token 刷新**：`access` 过期（401）时调 `/api/auth/refresh/`，刷新后**用新 refresh 覆盖旧值**。
3. **试卷详情 vs 列表**：列表无题目内容；详情（`GET /api/exam/papers/{id}/`）内嵌 `paper_questions`，每题含完整题目对象，无需再逐题查询。
4. **外键 ID**：所有外键字段（school/region/class/course/chapter/paper/question 等）填**数字 ID**，需先查对应列表接口拿真实 ID，勿写死。
5. **唯一约束**：`paper-questions` 的 `(paper, question)` 唯一；改分值/题号用 PATCH 只传 `sort/score`。
6. **文件上传**：资源上传、成绩导入、课外成果上传均为 `multipart/form-data`，注意字段名（`rtype`/`file`/`image`）。
7. **软删除**：DELETE 后记录 `is_deleted=true`，列表/详情自动过滤，前端看不到即视为删除。
8. **Decimal 类型**：分数字段可能返回 string 或 number（见 6.2），前端做 `Number(x)` 归一处理。
