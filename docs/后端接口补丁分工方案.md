## 二、为什么这样切（文件冲突分析）

`apps/exam` 下多个文件被不同模块共享，是冲突高发区。按上述切分，**每个文件只被一个人改**：

| 文件 | 唯一负责人 | 说明 |
|------|-----------|------|
| `models.py` | A | 两个新模型统一由 A 加，B/C 不碰 |
| `migrations/` | A | 迁移编号 0007/0008 必须由一人统一生成，避免各自编号冲突 |
| `urls.py` | A | 3 个 router 注册统一由 A 加 |
| `practice_views.py` | B | 全新文件，天然无冲突 |
| `views.py` / `student_views.py` / `serializers.py` | C | 两个模块都在 exam，归同一人，避免 B/C 同时 append serializer 冲突 |
| `questionbank/*` | A | 独立 app，与 exam 无交叉 |

> 关键：`serializers.py` 里两个新类（`FunContentSerializer`、`UploadedCertificateSerializer`）**都归 C**，从根本上避免最常见的冲突点。

## 三、各人详细任务

### A —— 组长 / 统筹

1. **数据层**：在 `apps/exam/models.py` 新增 `FunContent`、`UploadedCertificate` 两个模型（字段见《实施说明》）。
2. **迁移**：生成 `0007_uploadedcertificate.py`、`0008_fun_content.py`，并本地 `migrate` 验证通过。
3. **路由**：在 `apps/exam/urls.py` 注册 `practice` / `fun-contents` / `cert-uploads` 三个 router（视图类由 B/C 提供，A 负责接线）。
4. **模块4 试题资源**：`questionbank/urls.py` 注册 `resources`，`questionbank/views.py` 新增 `QuestionResourceViewSet`，`serializers.py` 新增 `QuestionResourceSerializer`。
5. **数据库变更记录**：在 `docs/database/` 生成两张新表的变更记录（含 SQL、类型、日期、修改人）。
6. **线上配置修复**：`DEBUG` 切 prod、`CORS` 白名单、`/media` 映射、确认 MySQL（见《实施说明》第五节）。
7. **合入与部署**：review B/C 代码 → 合入 → `migrate` → `collectstatic` → 重启 → 跑验证脚本。

### B —— 模块1 学生练习测评

1. 新建 `apps/exam/practice_views.py`，实现 `PracticeViewSet`（`permission_classes=[has_role(User.ROLE_STUDENT)]`）。
2. 三个接口：`random`（随机组卷+建答卷）、`sheets`（我的练习记录）、`{id}/sheets`（详情+正确率统计）。
3. 抽题规则按《实施说明》实现（学科过滤、年级过滤、题型数量、不足自动降级、空则 400）。
4. 复用 `apps/exam/services.py` 的 `sheet_payload / question_payload / resource_payload`，**不要重复实现**。
5. 自测：POST `random`、GET `sheets`、GET `{id}/sheets` 三条路径。

### C —— 模块2 趣味课堂 + 模块3 证书上传

**模块2 趣味课堂**（`apps/exam/views.py` + `serializers.py`）：
1. `FunContentViewSet`：列表/详情（学生、省级）、新增/改/删/发布/撤回（仅省级）。
2. 学生可见范围过滤：`status=published` 且 `school/target_class` 匹配本人。
3. 省级管理全部；`creator/school` 后端注入。
4. `FunContentSerializer`（含 `subject_display/status_display/creator_name/school_name` 等展示字段）。

**模块3 证书上传**（`apps/exam/student_views.py` + `serializers.py`）：
1. `UploadedCertificateViewSet`：上传（multipart+校验）、我的列表、软删、教师审核列表、教师审核（非本班 404）。
2. 上传校验：`image` 必填、仅 jpeg/png、≤5MB、`title` 截断 128。
3. `UploadedCertificateSerializer`（含 `cert_type_display/status_display/student_name/class_name/image_url` 等展示字段）。
4. 自测：上传、列表、审核（教师）、删除。

## 四、执行顺序（关键路径）

```
① A 先落地「数据层 + 迁移 + 路由」（models / migrations / urls）并合并到主线
        │
        ▼
② B、C 拉取最新代码，各自开分支开发（互不冲突，可并行）
        │
        ▼
③ 各自用 curl 脚本自测（13 条路径应 401/405，而非 404）
        │
        ▼
④ A review + 合入 + 部署（migrate / collectstatic / 重启）
        │
        ▼
⑤ A 处理线上配置修复 + 前端页面自检清单联调
```

> B、C 的业务代码依赖 A 先建好的模型与路由，因此 **① 必须最先完成**。

---

## 五、验收标准（三人共同对齐）

1. **13 条路径**全部返回 401/405（见《实施说明》第七节验证脚本）。
2. 响应体为几十字节 JSON，无 KB 级 HTML 调试页（说明 `DEBUG` 已关）。
3. 前端页面自检（《前端补丁说明》第七节）：
   - 学生端 首页/学科测评/资源中心/综合素质/我的证书 无 404 Toast；
   - 教师端 证书管理 待审核列表可拉取、审核生效；
   - 题库端 试题资源管理 可列表/改类型/删除；
   - 省端 趣味课堂 新增→发布→学生端可见，撤回后消失。

## 六、风险与约定

1. **数据库授权**：两模型建表属于数据库变更，须先按规范授权并留变更记录，否则 `migrate` 不要执行。
2. **迁移勿各自生成**：`0007/0008` 编号由 A 统一，B/C 若发现需要改模型字段，先找 A。
3. **`.env` / `settings` / 数据库配置**：部署时保留服务器现有配置，整目录覆盖 `apps/exam`、`apps/questionbank` 即可。
4. **回滚**：`migrate exam 0006` 会删两张新表，含学生已上传证书数据，回滚前先导出。
