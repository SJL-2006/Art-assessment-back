## 记录五：修复「题库管理员-课程管理·查看试题（题量多的课程）预览不到/只显示 80 道」

- **需求**：题库管理员端「课程管理」点击某课程的「查看试题」，对题量较多的课程（如 美术 143 道、初中音乐 165 道）预览弹窗里看不到全部试题。
- **根因**：`viewQuestions()` 只请求一页 `page_size: 80`，受后端分页上限（`max_page_size=100`）与单页条数限制，超过 80 道的课程只能预览前 80 道；对题量更大的课程后续试题完全看不到。
- **修改人**：userName（`git config user.name`）
- **修改日期**：2026-11-18 15:51:39
- **数据库变更**：无（纯前端调整，未改动表结构或数据）。

### 删除代码记录

`ART-front/frontend/src/views/questionbank/CourseList.vue`（前端，独立仓库）

- `viewQuestions()` 中「仅请求一页 `page_size: 80`」的旧实现：
  ```js
  const res = await api.questionbank.questions({ course: item.id, page_size: 80 })
  courseQuestionList.value = (res?.list || []).map(mapQuestion)
  ```

### 新增代码记录

`ART-front/frontend/src/views/questionbank/CourseList.vue`（前端，独立仓库）

- `viewQuestions()` 改为**分页循环拉取该课程全部试题**：每页 `page_size: 100`（后端上限），按 `total` 与每页实际返回条数判断是否继续翻页，直到取满 `total` 或出现不足一页为止，再把所有页合并后 `map(mapQuestion)` 展示。
- 合并后的逐条映射改为**单题 try/catch**：某一道题映射失败仅跳过该题并 `console.warn`，不再因单题异常导致整页清空；接口返回 `total > 0` 但列表为空时 `console.error` 便于定位。

### 校验结果

- 后端分页：`GET /api/questionbank/questions/?course=2&page_size=100&page=2` → 返回 `{list: 43, total: 143}`，确认 `page` 参数与 `total` 口径正常。
- 前端构建：`npm run build` ✓ built in 11.19s（`CourseList-*.js` 已重新生成）。
