## 记录一：修复快速组卷 404「资源不存在」（试卷 creator 注入与数据范围收敛）

- **需求**：科任教师端「快速组卷」创建试卷成功后，紧接着的 `detail` / `draft` 请求返回 404。根因：`PaperViewSet` 未实现 `perform_create`，且 `PaperSerializer` 的 `creator` 可写，前端不传导致新试卷 `creator=NULL`；教师按 `creator=user` 收敛范围时看不到自己刚建的试卷，`get_object()` 抛 404。学校/区县/市州管理员同理（`creator__school_id` / `creator__school__region_id` 匹配不到 `creator=NULL` 或没有 school 的自己）。
- **修改人**：userName（`git config user.name`）
- **修改日期**：2026-11-27 20:10:36
- **数据库变更**：无（本次为纯代码修复，不涉及表结构变更）。

### 删除代码记录

1. `apps/exam/views.py`：`_apply_paper_scope` 原市州/区县/学校三个分支仅按「创建人所属范围」过滤：

   ```python
   if user.role == User.ROLE_CITY:
       return qs.filter(creator__school__region_id__in=services.visible_region_ids(user))
   if user.role == User.ROLE_DISTRICT:
       return qs.filter(creator__school__region_id=user.region_id)
   if user.role == User.ROLE_SCHOOL:
       return qs.filter(creator__school_id=user.school_id)
   ```

   上述逻辑会把「本人创建的试卷」排除在外（区县/市州管理员没有 school，自建试卷 `creator.school_id` 为 NULL，`creator__school__region_id` 匹配不到），造成自建试卷不可见。

### 新增代码记录

1. `apps/exam/serializers.py`：`PaperSerializer.Meta` 增加 `read_only_fields = ["creator"]`，禁止前端在创建/更新试卷时写 `creator` 字段。

2. `apps/exam/views.py`：`PaperViewSet` 新增 `perform_create`，创建试卷时由后端注入当前登录用户：

   ```python
   def perform_create(self, serializer):
       """试卷创建人由后端注入，禁止前端伪造 creator。"""
       serializer.save(creator=self.request.user)
   ```

3. `apps/exam/views.py`：`_apply_paper_scope` 重写为「管辖范围 + 本人创建」合并（`Q` 已在该文件顶部导入），保证区县/市州/学校管理员能看到自己创建的试卷：

   ```python
   if user.role == User.ROLE_CITY:
       region_ids = services.visible_region_ids(user)
       return qs.filter(
           Q(creator=user)
           | Q(creator__school__region_id__in=region_ids)
           | Q(creator__region_id__in=region_ids)
       )
   if user.role == User.ROLE_DISTRICT:
       return qs.filter(
           Q(creator=user)
           | Q(creator__school__region_id=user.region_id)
           | Q(creator__region_id=user.region_id)
       )
   if user.role == User.ROLE_SCHOOL:
       return qs.filter(Q(creator=user) | Q(creator__school_id=user.school_id))
   ```

### 新增代码记录

1. `apps/exam/management/commands/seed_certificate_data.py`（新增文件）：

   - 命令 `python manage.py seed_certificate_data`，参数：`--dry-run` / `--limit N` / `--districts` / `--per-class`（默认 4，1-10）/ `--uploads-per-class`（默认 3，3-6）/ `--reset` + `--yes`。
   - 前置检查：`School` / `ClassRoom` / `ClassStudent(status=approved)` 任一为空则报错提示先执行 `seed_chengdu_data`；不新建学校/班级/学生。
   - 每所学校：为 music / art 各建一张演示试卷（`title` 以 `【演示】` 前缀为清理标记，`creator` 取该校 `role=school` 管理员，缺则任一教师）+ 一条 `PaperPublish`（`scope_type=school`）；无管理员/教师则跳过该校并警告。
   - 已颁发证书：每班每学科取 `--per-class` 名学生（音乐取前 N、美术取第 N~2N-1、不足循环补齐），确定性 `random.Random(f"{class.code}-{subject}")` 按 30% 优秀(85-98)/50% 良好(70-84)/20% 合格(60-69) 生成 `AnswerSheet`（`is_submitted=True`），再按 `(paper, student, publish)` 复用后生成 `Certificate`（`file` 留空）。批量 `bulk_create(batch_size=500)`。
   - 上传待审核证书：每班生成 `--uploads-per-class` 条 `StudentCertificate`，模板循环保证含 pending/approved/rejected 三种状态；`note` 以 `[演示数据] ` 前缀标记；审核人优先级 = 该班对应学科 `ClassTeacher` → 班主任 → 校管理员；`image` 复用 6 张共享模板图片（相对路径 `cert-uploads/seed/*.png`），不为每条记录生成独立图片。
   - 共享模板图片：`_ensure_seed_images()` 用 Pillow 生成 720×480 米白底 + 金色双边框 + 红色圆形印章 + 英文文字（`ImageFont.load_default()`，不依赖中文字体），6 张文件已存在则跳过。
   - 幂等：`Paper` 按 `title`、`PaperPublish` 按 `(paper, target_school)`、`AnswerSheet` 按 `(paper, student, publish)`、`Certificate` 按 `(student, sheet)`、`StudentCertificate` 按 `(student, title)` 查重；`--reset` 仅删除 `【演示】` 试卷与 `[演示数据]` 上传证书（且按 `--limit`/`--districts` 范围收敛），保留共享图片与其它数据。
   - 性能：按学校循环，每校一个 `transaction.atomic()`；每 10 所学校打印一次进度。
