# 代码修改记录 · 2026-11-13

## 记录一：修复「试题管理·分类选音乐无题」bug

- **需求**：题库管理员端「试题管理」页，学科（分类）筛选选「音乐」后列表为空，但数据库中实际存在音乐题。
- **根因**：前端「学科/分类」筛选只在**当前分页（12 条）**内做客户端二次过滤，未传给后端；而试题默认按 `-id` 排序分页返回，音乐题分散在不同页，选中「音乐」时当前页常无（或极少）音乐题，表现为「根本没有题」。同时后端 `course` 筛选只接受单个课程 id，无法表达「音乐」这一跨多课程的学科（音乐拆分为 音乐鉴赏/高中音乐/小学音乐/初中音乐，`code` 均为 `music`）。
- **修改人**：userName（`git config user.name`）
- **修改日期**：2026-11-13
- **数据库变更**：无（未改动表结构，未新增/修改/删除字段、表、索引或约束）。

### 删除代码记录

`ART-front/frontend/src/views/questionbank/QuestionList.vue`（前端，独立仓库）

- `filteredList` 计算属性中删除「学科」的客户端二次过滤一行：
  `if (filterSubject.value && row.subject !== filterSubject.value) return false`（改为注释说明已走服务端过滤）。

### 新增代码记录

1. `apps/questionbank/views.py`（后端，修改）

   `QuestionViewSet.get_queryset` 新增 `subject` 筛选参数：
   - `subject=music` / `subject=音乐` → `filter(course__code="music")`；
   - `subject=art` / `subject=美术` → `filter(course__code="art")`。
   - 通过课程代码聚合「音乐」下所有课程，与既有 `course`（单个课程 id）筛选并存、互不影响。

2. `ART-front/frontend/src/views/questionbank/QuestionList.vue`（前端，修改）

   - `serverParams()` 新增：`if (filterSubject.value) p.subject = filterSubject.value === '美术' ? 'art' : 'music'`，将学科筛选下发给后端；
   - `filteredList` 移除学科客户端过滤（见上方删除记录），学科标签展示逻辑（`subjectOf`）保持不变。

### 校验结果

- `python manage.py check`：✓ System check identified no issues (0 silenced)。
- 后端筛选计数：`course__code="music"` → 168 道；`course__code="art"` → 141 道（与数据库音乐/美术题量一致）。
- 前端：`src/views/questionbank/QuestionList.vue` 改动后学科筛选改为服务端分页过滤，选「音乐」可按全量（168 道）翻页浏览。
- 注意：前端若以 `dist/` 部署，需在 `ART-front/frontend` 下执行 `npm run build` 重新构建后生效。

## 记录二：试题列表默认排序改为「按学科 → 年级」分组

- **需求**：试题列表默认按 `id` 倒序（最新在前），音乐/美术/各年级混排、观感乱；改为按学科分组（音乐在前、美术在后），组内按年级（一年级…高三）有序。
- **修改人**：userName（`git config user.name`）
- **修改日期**：2026-11-13
- **数据库变更**：无（仅调整查询排序，未改动表结构或数据）。

### 删除代码记录

`apps/questionbank/views.py`（修改）

- `QuestionViewSet.queryset` 由 `Question.objects.all()`（依赖模型 `Meta.ordering = ["-id"]`）替换为显式分组排序查询；无删除的既有业务逻辑（仅替换 queryset 定义）。

### 新增代码记录

`apps/questionbank/views.py`（修改）

1. 顶部新增 import：`from django.db.models import Case, IntegerField, Value, When`。
2. 新增 `GRADE_ORDER` 排序键：`_GRADES`（一年级…高三 → 1…12），空值/未知年级 → 13 排最后。
3. `QuestionViewSet.queryset` 改为：
   - `select_related("course", "chapter")` 预取课程/章节，避免列表 N+1 查询；
   - `annotate(subject_order=…)`：`course.code` 为 `art` → 1（美术），否则 → 0（音乐）；
   - `order_by("subject_order", GRADE_ORDER, "id")`：学科分组 → 年级有序 → id 稳定排序。
   - 说明：模型 `Meta.ordering = ["-id"]` 保持不变，仅试题列表接口的默认排序改变；前端显式传 `?ordering=` 时仍以该参数为准。

### 校验结果

- `python manage.py check`：✓ System check identified no issues (0 silenced)。
- 默认列表排序验证：音乐 168 道全部在前、按年级（一年级→八年级）有序；美术 141 道全部在后；合计 309 道，学科/年级分组正确。
- 数据库中年级取值仅 8 种（一年级…八年级），均在 `_GRADES` 映射内，无遗漏。
